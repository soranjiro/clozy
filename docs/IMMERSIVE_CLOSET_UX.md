# Clozy — 没入型3Dクローゼット 要件定義 v1

作成日：2026-11-01／状態：設計提案。アプリへの適用・3Dアセット制作は未実施。

## 1. 体験の核

**服の一覧を開くのではなく、自分のクローゼットの中で、ハンガーを滑らせ、服を手前に取り出し、今日の組み合わせを選ぶ。**

- 起動先は開いたクローゼット内部。常設ヘッダー・タブバー・サイドバーは置かない。
- 上部はトップスのハンガーレール、中央は独立したボトムスレール、下部は段のあるシューズラック。長いコート・ワンピースには左側の縦長区画を確保し、裾がボトムスに突き抜けない。
- バッグ・アクセサリーは側面フックと浅い引き出し。衣替え収納は上棚の箱。機能の住所は毎回同じ。
- 中心行動は「探す→取り出す→合わせる→着用を記録」。空間を移動しても、服と収納の関係が理解できる。
- 3Dモデルは利用可能と仮定する。ただし現在の服データは写真中心なので、写真・シルエットでも同じ操作が成立する。
- コンセプト画像は文字・数字・説明ラベルを一切使わない。実製品のフォーム、検索、日付、確認、エラーには必要な日本語を表示する。

## 2. 想定利用と優先順位

| 優先度 | 利用場面 | 完了条件 |
| --- | --- | --- |
| P0 | 朝、着る服を選ぶ | レールから選び、組み合わせを記録できる |
| P0 | 所有服を探す | 横送り・検索・季節/お気に入りで目的の服に到達 |
| P0 | 服を追加・直す | 写真付き/写真なしで登録・編集・削除できる |
| P0 | 快適に操作する | タッチ・マウス・キーボード・読み上げで完了可能 |
| P1 | 履歴と手持ちを見直す | 日付別着用記録、既存の集計へ到達 |
| P1 | 衣替えする | 収納/取り出しが履歴を保持して反映される |
| P1 | 設定・バックアップ | 既存の任意アカウント、手動バックアップ、ロックへ到達 |
| P2 | 自分好みの収納にする | レール内の手動並べ替え、素材/照明の個人設定 |

P0から既存のP1機能への入口も確保する。機能を削って没入感を作らない。着せ替えシミュレーション、身体寸法の再現、天候連携、AI推薦、写真からの自動3D化は本仕様の対象外。

## 3. 空間・カメラ・画面

### 空間構成

正面性の強い浅い透視投影。自由歩行・360度回転は採用せず、家具の内側にいる視点を維持する。固定したワールド座標で、棚・光・服の位置が状態間で連続する。

- **全景**：3収納領域の関係を最初に示す。390×844の基準画面では上部約40%、ボトムス約28%、靴約22%、残りを枠・間隔・安全領域に配分。長い服は左側の独立区画。
- **トップス**：上部レールへ接近。中央の服は正面に近く、左右は斜め・一部重なりで続きが分かる。
- **ボトムス**：目線を中央へ下げる。クリップハンガーと吊るされたパンツ/スカートで上部と区別。
- **シューズ**：さらに目線を下げ、少し見下ろす。左右一組を1アイテムとして、棚から手前に引き出す。
- **取り出し**：選択した服のみ手前に移動。元のレールには空いた隙間を残す。背後の家具は消さず、照度を少し下げる。
- **コーデ**：側面の引き出し式サブレールにトップス・ボトムスを上下に配置。靴は下の引き出しトレー。同じ家具の中で完成する。

320px幅や拡大時には全景を無理に詰めず、下部が自然に続く縦スクロールにする。横長画面では3収納の関係を維持して家具を広げる。タブレット/PCに固定メニューを復活させない。

### 6つのビジュアル状態

| ID | 画像の読み順 | 伝える内容 | 次の行動 |
| --- | --- | --- | --- |
| S01 | ボードA・左 | トップス/別レールのボトムス/下段の靴の全景 | 収納領域をタップ |
| S02 | ボードA・中央 | レール上の服を横送り、中央の1着に間隔が開く | タップで取り出す |
| S03 | ボードA・右 | トップスを取り出し、元のハンガー位置が空く | コーデへ加える/戻す |
| S04 | ボードB・左 | クリップハンガーのボトムスを探索 | ボトムスを選ぶ |
| S05 | ボードB・中央 | 靴の一組を棚からトレーごと手前へ出す | 靴を選ぶ |
| S06 | ボードB・右 | 同じ収納内で上下と靴が揃う | 明示操作で着用記録 |

画像は方向性を示す静止画。操作判定・アニメーション・可用性が実装済みであることの証明には使わない。

## 4. ヘッダー・タブバーを使わないナビゲーション

| 場所/物体 | 操作 | 到達先 |
| --- | --- | --- |
| 各レール・靴棚 | タップ/クリック | 対象領域へ接近 |
| 右側の真鍮の取っ手（虫眼鏡刻印） | タップ | 検索・絞り込み・全機能一覧を収めたユーティリティ引き出し |
| 空のハンガー（＋刻印） | タップ | 服追加/まとめて登録 |
| 側面の補助レールの取っ手 | タップ | コーデ確認・既存ルールの候補 |
| 下部の記録用引き出し | タップ | カレンダー/分析 |
| 引き出し内の歯車 | タップ | 設定・アカウント・手動バックアップ |
| 接近時の小さな戻る操作 | タップ/Escape/ブラウザ戻る | 直前の空間と選択位置 |

主要ユーティリティの取っ手は家具の右端、安全領域内に常に1つ露出させる。小画面でもスクロールで失わず、家具の縁に沿って追従する。横並びのボタン帯にしない。カメラ移動に追従するDOMボタンで、3Dメッシュが隠れてもアクセス可能。

取っ手から検索・追加・コーデ・履歴・分析・設定へ2操作以内で到達。初回のみ短い日本語の操作案内を閉じられる形で表示する。ホバー/フォーカス/長押しで名称を表示し、読み上げ用名称は常に持つ。家具の意味を推測しなくても「機能一覧」を選べる。

扉開閉は任意。毎回閉じた扉を開けさせない。戻ってきたら直前の収納・中央アイテムを復元する。

## 5. 操作仕様

### 縦探索と横送りの競合解決

- 縦方向：通常のブラウザスクロールでトップス→ボトムス→靴へ目線を移動。1pxのスクロール量に連続したカメラ位置を対応させる。全画面の強制ページ送りやスクロール封鎖はしない。
- 横方向：レール/ラックの領域でスワイプ。家具・他レールは静止したまま対象だけ動く。
- タッチ開始から8 CSS pxまではタップ候補。横移動が縦の1.3倍を超えた時に横送りと判定。それ以外は縦スクロール優先。数値は試作時に実機調整する。
- レールはDOMの横スクロール面を操作の基準にし、`touch-action: pan-x pan-y pinch-zoom`とブラウザの標準軸判定を利用する。ネイティブ縦スクロール開始後に横へ奪わない。ページ全体の`preventDefault`は禁止。
- 画像タップは移動8px以内・300ms以内を初期値とし、スクロール終了直後の誤タップを抑止する。長押しだけに必須操作を割り当てない。
- 慣性後は最寄りアイテムへ穏やかにスナップ。端で無限ループしない。並び順は名前/登録日等の明示選択で変える。
- ホイール縦移動は空間探索。Shift＋ホイール/トラックパッド横はレール送り。キーボードはTabで収納に入り、左右で前後、Enterで選択。上下キーを奪ってページ移動を壊さない。
- レールの前後ボタンをフォーカス時に表示。スワイプが難しい人も同じアイテムへ到達できる。

### 服を選ぶ

1. 横送りの中央に来た服は左右に隙間が開き、明るさが少し上がる。この段階では未選択。
2. タップするとハンガーごと手前へ約15〜20cm移動し、正面を向く。選択状態をDOMと3Dで一致させる。
3. 選択中は回転ハンドル/左右操作で前後面を確認。自由なカメラ旋回はしない。裏面モデルがない場合は回転を無効化し、写真裏面を捏造しない。
4. ハート・コーデに追加・詳細/編集・戻すを局所的に表示。アイコンにはラベルを呼び出せる。削除は詳細内から明示確認。
5. 空間の空き部分タップ/戻るで元の位置へ。ドラッグしてコーデレールへ置く操作は補助とし、「コーデに追加」ボタンでも完了可能。

### コーデと着用記録

- トップス・ボトムス・靴は選択ごとにサブレール/トレーへ複製表示し、元の服データは移動・消去しない。探索中の取り出し表現とは区別する。
- 初期はトップス1/ボトムス1/靴1、アウター等は追加可能。ワンピース選択時は上下の代わりになることを明示し、既存候補ルールと整合させる。
- 同一スロットの追加は入れ替え候補を示し、確定まで以前の選択を保持。外す操作を提供する。
- 欠けたカテゴリがあっても利用者の判断で記録できる。所有していない服の推薦画像を混ぜない。
- 「今日着た」操作で日本時間等の端末ローカル日付を確認して記録。別日指定も可能。選択だけでは着用履歴を作らない。
- 保存中は二重操作を抑止し、失敗時は選択を保持して再試行。成功後は記録済み日付と服を伝える。同じ日の重複は既存サービスで防ぐ。

## 6. 既存機能を空間へ接続

- 検索：名前・ブランド・色、既存の正規化済み検索を利用。季節/お気に入り/収納状態/カテゴリー/並べ替えは引き出しにまとめる。
- 絞り込み中は取っ手に小さな状態印を表示し、引き出し内に条件・件数・全解除を表示。該当ゼロを「服が消えた」と見せない。
- 登録：空ハンガーから既存フォームへ。登録後、カテゴリーに合う収納へ戻り、新規服を一時的に中央表示。写真なしも利用可能。
- 編集/削除：既存バリデーション、未保存確認、関連履歴の削除確認を維持する。
- 衣替え：収納操作は`archived`を更新。上棚の箱から収納中の服を検索・復帰できる。収納は削除ではない。
- 履歴/分析：既存画面を引き出しの内側に表示する読みやすいDOMパネルへ移す。数字や日付は装飾3D文字にしない。
- アカウント等：現在の認証・ローカルロック・手動バックアップのフローを再利用。見た目の移動でクラウド同期仕様を変えない。

## 7. 視覚設計

- 現在の木製家具表現から連続させる。ウォルナット`#503521`、オーク`#93633E`、真鍮`#C69E6A`、リネン`#FAF7F1`、文字`#32271F`を基準にする。
- 木目は大きな流れと控えめな粗さ。金属レールは細い反射、ハンガーは統一。服はニット/綿/デニム/革の素材差を持たせる。
- 上棚下の暖白色間接照明＋柔らかな補助光。奥行きは接地影と遮蔽で示す。服の固有色を損なう強い黄かぶり、強いブルーム、黒潰れは避ける。
- 中央の服が最も読みやすい大きさ。選択対象を奥の服に埋めない。重なりが強い箇所は余白を開け、隣へ送れることが分かる端の見切れを残す。
- アイコンは同じ線幅。触れる物体は取っ手、刻印、陰影で示す。装飾品をボタンのように光らせない。
- 詳細パネルは棚から現れるリネン色の平面。入力・確認はコントラストを優先し、木目の上に小さな本文を直接置かない。
- 暗い環境でも操作が見える。文字は通常4.5:1、大きな文字と操作境界は3:1を設計目標とし、実レンダリングで確認する。
- コンセプト画像の木材・服・光は参考。架空の服を利用者の所持品として本番に混ぜない。

## 8. 動き・音・触覚

| 動作 | 初期時間/振幅 | 表現・中断 |
| --- | --- | --- |
| 初回空間表示 | 300〜450ms | 照明が柔らかく立ち上がる。操作は即時有効 |
| 収納への接近 | 320〜420ms | 家具の位置関係が残る平行移動＋小さなズーム。再入力で更新 |
| レール送り | 指に1:1追従 | 遅延イージングなし。離した後180〜280msで整列 |
| ハンガーの揺れ | 最大±2度、350〜550ms | 動かした近傍だけ減衰。常時揺らさない |
| 服の取り出し/戻し | 280〜380ms | 前へ移動→正面化。元の隙間を保持 |
| 靴トレー | 240〜320ms | 棚板に沿って引き出す。靴が空中浮遊しない |
| 引き出し | 240〜320ms | 物理移動とDOMパネルの出現を同期 |
| コーデへの追加 | 300〜450ms | 同じ服の移動先を追える。連続追加を受け付ける |
| 保存完了 | 150〜200ms | チェックと短い通知。大きなカメラ演出なし |

- 数値はプロトタイプの初期値。短い操作を演出終了待ちにしない。状態更新はアニメーション完了コールバックだけに依存しない。
- スクロール中に重い被写界深度や影更新を行わない。画面振動・カメラの呼吸・自動周回・ジャイロ追従を入れない。
- 動きを減らす設定では慣性の追加演出、揺れ、視点補間を停止。収納位置は即時切替、短い不透明度変化までにする。
- 音は既定オフ。任意で静かなレール音/引き出し音。触覚は利用可能端末で任意の短い選択通知。音/振動だけで成功を伝えない。

## 9. データ状態・障害

| 状態 | 必須挙動 |
| --- | --- |
| 初回0件 | 空の各レールと靴棚を見せ、中央の空ハンガーから追加。サンプルを登録済み風に表示しない |
| 特定カテゴリー0件 | 空き収納＋カテゴリに合う追加導線。他カテゴリーへ移動可能 |
| 検索0件 | 条件と解除操作。保存データを消さない |
| モデル読み込み中 | 同じ服の写真/シルエットで即操作。完成待ちで画面を遮断しない |
| 3Dモデル失敗 | その服だけ写真へ切替。再試行可能 |
| WebGL不可/context lost | 全収納をDOMの横送りUIで利用。選択・検索・コーデを保持 |
| データ読込失敗 | エラーと再試行。空クローゼットとして誤表示しない |
| 保存失敗 | 編集/選択を保持。理由を表示、再試行 |
| 服の削除/カテゴリ変更 | 選択参照を検証し、隣接服/新収納へ移す。消えたIDを選択し続けない |
| バックグラウンド/ロック | 描画停止。既存ロックを優先、解除後にデータを再検証 |

## 10. アクセシビリティ・レスポンシブ

- 3Dキャンバスは視覚表現。服一覧・選択・操作にはDOMの同等構造を持ち、二重読み上げを避ける。
- 服の読み上げは名前、カテゴリ、選択状態、位置。お気に入り等の変化は必要な時だけ通知し、フレームごとに読み上げない。
- ターゲットは44×44 CSS px以上。細い取っ手は見た目と別に透明な押下領域を確保し、隣接領域を重ねない。
- 表示上の重なりは押下領域の優先順位と一致。DOMのフォーカス位置も見えている服と同期する。
- 引き出し/詳細は適切なダイアログ構造。開いた先へフォーカス、閉じたら元の物体へ復帰。Escape、戻る、明示閉じるを提供。
- ピンチ拡大、200%表示、読み上げ、片手操作に対応。システムの端スワイプとホーム領域を避ける。
- 320/390/430/768/1440px幅と、横向き・ソフトキーボード表示を確認。固定の絵を縮小して済ませない。

## 11. 性能・アセット目標

目標値であり実測結果ではない。基準端末/回線は実装開始時に記録して固定する。

- 基準：iPhone 12のSafari、同等世代AndroidのChrome、一般的PC。通常操作は60fps目標、低品質設定で安定30fps以上を目指す。
- 初期3D転送は圧縮後5MB以下、初回は家具＋目に入る服だけ。全所有服の3Dモデルを同時ロードしない。
- 通常4G相当の検証条件で2.5秒以内に写真/DOM版で操作可能を目標。3Dは遅延読み込み。永久オフライン対応は別仕様。
- 初期DPR上限1.5、低品質1.0。モデル解像度/影/後処理を段階的に下げる。停止中は必要時描画、非表示時は停止。
- 視界内＋前後2着を優先してロード。レールの論理件数と描画件数を分離。100/500/1000件でメモリと検索・スクロールを検証。
- アセットはGLBを候補とし、メートル単位、適切な原点、レール接点、カテゴリー別境界を統一。トップスは襟/ハンガー、ボトムスは腰クリップ、靴は靴底中央を基準にする。
- 前/後面の有無、実寸ではなく表示基準寸法、LOD、写真への代替をアセット台帳に記録。
- ユーザー写真を外部生成API/CDNへ送らない。静的アセットは同一オリジン。現在の写真データ・バックアップを3D化のために移行しない。

## 12. 受け入れ条件

1. S01〜S06を同じ家具・服・照明の連続状態として再現する。全景で上下レールと靴棚が識別できる。
2. ヘッダー/タブバー/サイドバーなしで検索・追加・コーデ・履歴・分析・設定に到達できる。
3. 横スワイプ中にページが意図せず移動せず、縦スワイプは自然にスクロールする。斜め/端/素早い連打を実機確認する。
4. 服の中央表示、取り出し、コーデ追加、着用保存の4状態を混同しない。失敗時も選択が残る。
5. 服を登録/編集/削除/検索/収納/復帰でき、既存の写真・履歴・バックアップに損失がない。
6. 3Dなし、モデルなし、写真なし、動きを減らす設定、キーボードのみでも主要タスクを完了できる。
7. 320px幅と200%拡大でページ横溢れ・操作重なり・閉じられないパネルがない。
8. 通信/保存失敗、WebGL喪失、ロック復帰の試験を実施する。設計画像の確認だけで完了としない。
